# 猫猫对对碰 规则定稿 v0.1（2026-09-03）

## 基本元素
- 乌龟颜色：N = 9（暂定）
- 卡包：基础卡包开出 1 只随机颜色乌龟（均匀分布，暂定）；未来可能有更多卡包类型
- 玩家初始卡包数：X（数值待定）
- 棋盘：3×3 九宫格（棋盘与规则绑定，未来可能有其他棋盘）

## 幸运色（2026-09-03 新增）
- 开局玩家从 9 色中选一只幸运乌龟（也可随机）
- 判定完成后，被消除的每只幸运色乌龟额外 +1 卡包（reward.lucky），计入本轮总返还
- 大满贯里必然恰有 1 只幸运色 → 实际 +11

## 一轮流程
1. 玩家点击唯一按钮「发牌」
2. 用卡包填满所有空格（填 k 格消耗 k 个卡包；卡包不足以填满时的处理待定）
3. 对整个盘面做一次判定（不连锁，消除产生的空格留到下一轮）
4. 结算返还卡包
5. 若本轮没有任何消除 → 棋盘上盖出「摇晃棋盘」按钮；摇晃后随机打乱全部格子位置，重新判定并结算
   - 每轮最多摇晃 shakeLimit 次（当前 1，可设 Infinity）；用尽仍零消除 → Run 结束
   - 摇晃不消耗卡包（暂定）
   - 若盘面不存在任何同色（如只剩孤龟），打乱也不可能消除 → 不提供摇晃，直接结束
6. 卡包耗尽 → Run 结束

## 判定顺序（前一步消除的乌龟，视为下一步不存在）
1. 大满贯：9 格 9 色各不相同 → 全消，+5
2. 连线碰：3 只同色成横 / 竖 / 斜一线（共 8 条线），每条 +5
   - 多条线同时成立时在同一盘面上一并判定，共享格子的两条线各自 +5（极罕见）
3. 对子碰：2 只同色同时在盘上即成对，不要求相邻，每对 +1
   - 已消除格子不参与；一只乌龟只能属于一个对子
   - 同色 3 只（未成线）= 1 对 + 1 只剩下；同色 4 只 = 2 对；同色 5 只 = 2 对 + 1 只
   - 实现上按颜色分组、按格子编号两两配对
   - 推论：一轮零消除时盘上颜色必然两两不同，打乱也凑不出连线，摇晃在正常流程下不再触发
4. 清空：判定结束后盘面为空 → 额外 +5
   - 大满贯必然清空，因此大满贯实际 +10

## Run
一次 Run = 从初始 X 个卡包开始，反复进行轮次直到结束。游戏核心乐趣是反复开 Run。

## 得分与结算（2026-09-03 改）
- **不按轮次计分。** 所有被消除的棋子都进入「暂存区」（按颜色计数，`state.stash`）
- Run 结束（无法再发牌：卡包耗尽 / 摇晃用尽仍零消除）时，**最终得分 = 暂存区数量 + 棋盘上剩余的棋子数量**
  - 推论：得分恒等于本局开出的卡包总数（`state.spent`），赚得越多、开得越多、分越高
- 结算界面：大数字展示最终得分（只），并展示**持有数量 Top3** 的款式（暂存区 + 盘上剩余合并统计，同数按颜色索引排序）
- 本地纪录改为「最高得分」；战绩图同步展示得分与 Top3
- 引擎接口：`Engine.tally(state, topN)` → `{ counts, stashed, onBoard, total, top }`

## 已定（2026-09-03 补充）
- 卡包不足以填满空格时：能填几格填几格，然后照常判定
- 结算演出：逐个结算。每条线、每个对子各自「高亮 → 消除 → 加卡包」，不一次性全消；清空奖励在最后单独结算
- 大满贯作为一个整体结算（9 格同时消），随后结算清空奖励

## 当前实现的数值（占位，待调）
- N = 9，X = 20，对子 +1，连线 +5，清空 +5，大满贯 +5
- 蒙特卡洛（2 万局 / 档）：X=20 时平均 5.0 轮、中位 4 轮、P90 10 轮；返还率约 34%
- **100% 的 Run 以「零消除」结束，卡包从未耗尽**；X 超过 20 后对 Run 长度几乎无影响

## 占卜（今日运势，2026-09-03 新增，取代「结束原因」）
- 指标：本局翻开的卡包总数（state.spent）
- 分布：预生成表 app/js/fortune-data.js（tools/build-fortune.js 离线跑 20000 局，玩家总是摇晃、幸运款随机）；运行时不做模拟。改数值后重新生成，pack.sh 会自动执行；签名不匹配时退回 600 局同步兜底并在控制台警告
- 百分位 = (严格更少 + 一半并列) / N；4 档：末吉 < 30% ≤ 小吉 < 60% ≤ 中吉 < 85% ≤ 大吉
- 每款有 4 句运势短句（skins.js fortune 字段），结算界面强调色取幸运款的特效主色，结算特效用幸运款自己的粒子预设
